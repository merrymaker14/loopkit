Resumen de LoopKit

Guía de LoopKit

Requiere Unity 6000.5.7f1. Incluye componentes estándar de Unity, un núcleo C# independiente y dos ejemplos importables. No necesita modelos ni servicios en línea. Interfaz y documentación en inglés, ruso, español y chino simplificado.

Comenzar en el Inspector

  1. Importa el paquete de Asset Store mediante Package Manager → My Assets → Import, o un .unitypackage local mediante Assets → Import Package → Custom Package. Para la distribución UPM, usa Package Manager → Add package from disk (package.json) o Add package from tarball (.tgz).
  2. Crea Strange Euphoria XR → LoopKit → Loop definition en Project. Asigna un ID estable y único; añade hechos y eventos.
  3. Añade LoopClockBehaviour, asigna la definición y configura hora inicial, velocidad y Tiempo del juego. Activa Iniciar al comenzar.
  4. Abre Tools → Strange Euphoria XR → LoopKit → Workbench. El idioma elegido también cambia los inspectores.

La distribución de Asset Store se instala en Assets/StrangeEuphoriaXR/LoopKit, con Documentation y Samples incluidos. UPM conserva las guías en Documentation~ y los ejemplos en Samples~; importa el ejemplo desde Package Manager → Samples antes de usarlo. Mantén una sola instalación de LoopKit por proyecto. Se requieren los módulos estándar Unity Audio, IMGUI, JSON serialization, Physics y UIElements; las integraciones opcionales se instalan aparte.

Recordar entre sesiones del juego

Activa Recordar entre sesiones del juego. Una casilla habilita carga y guardado automáticos de hechos permanentes y conocimientos persistentes. Las rutas relativas parten de Application.persistentDataPath; {definition} se sustituye por el ID escapado. Usa archivos distintos para juegos, ranuras o relojes independientes.

Con LoopKnowledgeAction, asigna reloj, observador player, ID del hecho, fuente y motivo. Elige Entre bucles y conecta Learn a un botón, activador o evento. Leer un hecho del mundo no lo enseña automáticamente.

Cargar inicia un bucle nuevo: cancela operaciones antiguas, espera su finalización real, sustituye la memoria permanente, restaura participantes y verifica el mundo. Se eliminan hechos y creencias temporales; una contradicción temporal no destruye el recuerdo permanente. Funciona con componentes Reset Transform registrados.

El guardado sigue cambios permanentes y reinicios correctos; también guarda al pausar o cerrar una aplicación inicializada. JSON admite 4 MiB; la sustitución es atómica y conserva el archivo anterior como .bak para recuperarlo a mano; LoopKit nunca carga .bak por sí mismo. Deben coincidir esquema, ID de definición y el conjunto de ID de hechos permanentes. Mover, añadir o quitar eventos del horario en una actualización mantiene válida la memoria guardada; añadir, quitar o renombrar un hecho permanente requiere otra ruta de memoria o tu propia migración. Con memoria automática activada, un archivo inicial inválido o una carga que inicia el reinicio pero falla al esperar/verificar mantienen desactivado el guardado automático, e Iniciar al comenzar no pone en marcha el reloj: el juego decide qué ofrecer al jugador. Una carga manual rechazada antes de la transición —por ejemplo, JSON inválido o una huella distinta— conserva la sesión activa: sus guardados automáticos continúan en la ruta seleccionada y pueden sustituir ese archivo tras un cambio permanente. El Inspector muestra detalles técnicos. Conserva el archivo y selecciona la ruta/definición correcta o una ranura migrada/nueva antes de continuar. El almacenamiento se comprobó en Windows; no es sincronización en nube ni serialización arbitraria de escenas.

Para continuar con las pistas de la sesión actual, llama explícitamente a LoopClockBehaviour.RecoverMemoryFromCurrentSession() después de un error de persistencia. Primero copia el archivo principal y .bak, si existen, en archivos separados terminados en .recovery-<unique-id>, junto al guardado. Solo después de completar ambas copias escribe atómicamente los hechos y conocimientos permanentes actuales; no importa pistas antiguas. Las copias de recuperación nunca se reemplazan, ni al reintentar. Un fallo de copia o escritura devuelve false, establece PersistenceError y mantiene desactivado el guardado automático; las pistas actuales permanecen en memoria. Start debe haber terminado y la sesión debe ser válida, fuera de una carga o grupo de eventos del Inspector. No reinicia, avanza ni inicia el bucle. Si la sesión está en error, corrige la causa y completa un reinicio correcto primero. The Last Bell muestra el error y la acción de recuperación en el menú de inicio/pausa. Elige esta acción cuando quieras convertir las pistas actuales en el nuevo guardado; los archivos originales permanecen en sus copias de recuperación.

Abrir una puerta a las 21:30

En la definición añade open_door, activa Usar hora del día y configura 21:30. Añade LoopCueEvents a un objeto activo, selecciona reloj y ese ID; conecta Actions a GameObject.SetActive(false) de la puerta. Añade LoopResetTransform a la puerta con reloj e ID únicos.

Cada evento se ejecuta una vez por bucle en orden estable. Los segundos son relativos al inicio; una hora anterior indica el día siguiente. Los ID y datos del autor no se traducen. Una llamada diferida conserva su marca original. Cada grupo UnityEvent es síncrono; RestartLoop, RestartAndRun y LoadMemoryFromEvent aplazan la transición hasta salir del grupo. Gana la última transición solicitada. El código que invoca directamente la sesión debe coordinar sus propios callbacks.

Mostrar un botón al conocer el código

Añade LoopKnowledgeGate, observador player e ID del hecho. Asigna el botón a Activar cuando se conoce; puedes exigir un valor concreto y añadir objetos/eventos para el estado desconocido. Se actualiza al sincronizar o al final del frame tras aprender, cargar o reiniciar. El reloj puede reactivar el objeto inactivo del propio componente. Mantén el reloj fuera de objetos controlados. Deshabilitar el componente detiene su evaluación. Los objetos de una escena cargada después del reloj deben estar activos al cargarla; si no, llama tú a BindClock() (y a RegisterInitialState() para Reset Transform).

Emma va a la cocina a las 22:00

Añade LoopTimedRoute con ID único y Transform del personaje. Crea marcadores inmóviles fuera de su jerarquía y puntos estrictamente crecientes, en segundos o HH:MM. Elige interpolación o cambio instantáneo. Las poses mundiales se capturan al vincularse. Advance/AdvanceTo colocan inmediatamente la pose exacta, incluso con saltos pequeños.

La ruta restaura y verifica su personaje. No añadas Reset Transform al mismo personaje: se diagnostica el conflicto. La ruta Transform no evita paredes. Para objetos creados durante la partida, asigna campos y llama BindClock() antes de modificarlos. Inventario, animación, cambios de padre/escala y recreación de objetos destruidos necesitan participantes propios.

LoopNavMeshRoute se habilita en un ensamblado opcional solo con com.unity.ai.navigation 2.x. Asigna NavMeshAgent y prepara un NavMesh adecuado. Guía el agente durante el avance normal a cualquier velocidad, se detiene con el reloj y hace Warp a la pose prevista al saltar, cargar o reiniciar. La verificación del reinicio acepta la posición inicial ajustada al NavMesh dentro del radio del agente. Una pose fuera del NavMesh hace fallar el reinicio y se informa en la Console. Los marcadores deben estar sobre la superficie. El paquete base no instala Navigation.

Pausa y explicaciones

Tiempo del juego usa Time.deltaTime; Time.timeScale = 0 detiene el reloj. Tiempo real ignora timeScale intencionadamente. Velocidad significa segundos del bucle por segundo de la fuente. La espera de reinicio siempre usa tiempo real. Los saltos manuales pueden avanzar un reloj pausado. También existen propietarios independientes Pause(owner)/Resume(owner).

Workbench muestra conocimientos filtrados por observador junto al diario de motivos. Selecciona una fila para ver fuente, motivo, alcance y tiempo completos. Horario distingue ejecutados/pendientes; Hechos muestra la realidad. Un personaje puede creer algo falso o anticuado. Verificación identifica problemas concretos. El diario conserva 512 registros, no un historial persistente ilimitado. Si un componente lanza una excepción al vincularse o actualizarse, LoopKit la registra en la Console con su objeto y sigue actualizando los demás; un error de actualización se informa una vez por bucle.

Ejemplos

En UPM, importa The Last Bell desde Package Manager → Samples. En la distribución de Asset Store el ejemplo ya está incluido. En un proyecto URP 17.5 con Unity 6000.5.7f1, abre Prepared/TheLastBell.unity dentro de la carpeta del ejemplo y entra en Play mode. En Asset Store la ruta es Assets/StrangeEuphoriaXR/LoopKit/Samples/LastBell/Prepared/TheLastBell.unity; tras importar desde UPM está en Assets/Samples/LoopKit/1.0.0/The Last Bell/Prepared. Prepared/Prefabs contiene 12 prefabs de modelos reutilizables. La escena y los materiales preparados requieren URP; el núcleo de LoopKit no depende de URP. Para Built-in Render Pipeline, elige Tools → Strange Euphoria XR → LoopKit → Create last bell scene para generar una escena con materiales Standard. El generador también sigue disponible en URP.

WASD/flechas: caminar; E: interactuar; Tab: pistas; Esc: pausa. El misterio requiere tres bucles: aprender el código, recoger un fusible y leer el manual, y finalmente aplicar pronto la secuencia y avisar al mensajero. Menú, pistas y final están en cuatro idiomas. Las pistas sobreviven al reinicio del Player; los objetos físicos no. La escena incluye modelos originales de Blender: estación, tren, patio, personajes y objetos del misterio. No requiere otro plugin ni modelos de IA.

A second chance es un ejemplo menor en inglés: lee 2417 después de seis segundos, reinicia y abre la puerta antes de que el mensajero salga a los cinco.

Núcleo, sistemas propios y MCP

CaptureCoreState/RestoreCoreState guardan reloj, prefijo de eventos, hechos y conocimientos. La carga solo de núcleo rechaza participantes del mundo. Usa CapturePersistentMemory/RestorePersistentMemory para conocimientos permanentes con un mundo reiniciado. Validan antes de modificar e invalidan operaciones antiguas. Mantén LoopWork hasta la finalización real. Un fallo deja el mundo detenido: corrige la causa y reintenta. Solo el hilo creador modifica la sesión; únicamente LoopWork.Dispose admite otro hilo.

LoopRehearsal.Run comprueba ramas lógicas, no física, imagen o navegación. MCP requiere exactamente Unity Pipeline 0.8.0-exp.1. Conecta mediante unity mcp --project-path <ruta-absoluta>. loopkit_status, loopkit_schedule, loopkit_knowledge, loopkit_reset_report son de solo lectura para reloj/observador elegidos. Otras versiones excluyen el adaptador. No hay servidor de control en Player.

Repetir el bucle automáticamente

Para un bucle automático, conecta el último evento a LoopClockBehaviour → RestartAndRun. El reloj continúa tras cancelar el trabajo anterior, esperar y verificar el reinicio. RestartLoop reinicia y detiene. Un reinicio fallido o sustituido por otra solicitud no inicia el reloj. Workbench y el Inspector en ejecución ofrecen Reiniciar y ejecutar. Los eventos observan las rutas Transform en la posición exacta de su instante, incluidos los saltos temporales. Las rutas NavMesh usan el movimiento normal del agente en los ticks y Warp al saltar/reiniciar; la navegación normal no garantiza llegar en el instante del evento. La memoria permanente modificada también se guarda al destruir un reloj activo si la sesión está preparada y es válida.

Versión 1.0.0

Incluye acciones y condiciones de conocimiento en el Inspector, memoria permanente, rutas temporales, verificación del reinicio y diagnóstico MCP de solo lectura en el Editor. The Last Bell ofrece un misterio de tres bucles con 12 modelos FBX originales; A second chance es un ejemplo más pequeño. Las herramientas del Editor, las guías, la referencia API y The Last Bell están disponibles en inglés, ruso, español y chino simplificado.
