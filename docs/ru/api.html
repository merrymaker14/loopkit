Обзор LoopKit

LoopKit — справка API

Пространства имён: StrangeEuphoriaXR.LoopKit — независимое ядро C#; .Unity — компоненты Unity и файлы; .Editor — диагностика и настройка.

using StrangeEuphoriaXR.LoopKit;

var loop = new LoopSession("courtyard-v1",
    new[] { new LoopCue("courier_leaves", 5, "courier", "leave", "gate") },
    new[] { new LoopFact("gate", "closed"), new LoopFact("code", "2417") });
loop.TryLearn(loop.Stamp, "player", "code", "2417",
    LoopLifetime.Persistent, "note", "Read the keeper's note.");
loop.AdvanceTo(6);
var reset = loop.BeginReset();
if (reset.Done && reset.Report.Succeeded) loop.Running = true;

Если операция не завершилась сразу, вызывайте reset.Tick(unscaledRealSeconds) из обновления игры до Done. У LoopClockBehaviour это уже реализовано.

API Контракт
LoopSession.SetSchedule Замена целого расписания при остановленных часах, нулевом времени и отсутствии незавершённой работы; проверка до изменения; порядок равных отметок сохраняется; до 10000 событий
ConfigureFacts До первого запуска, записей, сброса и создания работы; до 10000 описаний
Advance / AdvanceTo Неотрицательное конечное время до 315360000 секунд; обработчики видят точную отметку каждого события
Pause / Resume Сравнение владельцев по ссылке; каждый владелец снимает свою паузу, а сброс снимает паузы всех владельцев
Stamp / IsCurrent ID сессии и растущее поколение; отметка недействительна во время сброса, ошибки и после Dispose
BeginWork Дескриптор удерживается до действительного завершения задачи/нативной работы, а не лишь принятия отмены
TrySetFact Явная запись состояния мира; знание никому автоматически не выдаётся
TryLearn Наблюдатель, увиденное значение, срок, источник и причина; это отдельно от истины мира
Knowledge.TryExplain Последнее текущее знание с источником, причиной, временем и поколением получения
TryRecordDecision Принятие/отказ с причиной; само игровое действие не выполняется
Knowledge.Journal Последние 512 записей; диагностическая история, а не бессрочный надёжный журнал
Register(ILoopParticipant) Уникальный ID, отмена, восстановление и проверка; регистрация до сброса
Unregister(ILoopParticipant) Вне сброса удаляет сразу. Во время сброса сохраняет текущий snapshot и откладывает удаление до завершения, перед ResetFinished, в том числе при ошибке. Текущие callbacks/ожидание ещё могут вызываться; уничтожаемый участник должен это учитывать. Удаление не завершает рабочие дескрипторы.
BeginReset Остановка, инвалидация, отмена, ожидание, восстановление, проверка; тайм-аут по умолчанию 10 реальных секунд; автоматически не продолжает время
CaptureCoreState Только часы, факты, знания; запрещено во время обработки события или перехода
RestoreCoreState Совпадение схемы, описания и его отпечатка, корректный префикс событий; при участниках мира загрузка отклоняется
LoopCheckpointFile JSON до 4 МиБ, атомарная замена в одной папке и прежний файл .bak
LoopRehearsal.Run Фабрика новой логической сессии, явные действия и ожидания; системы сцены не симулируются; шаг ExpectKnowledge с пустым значением принимает любое известное значение

До 10000 пар наблюдатель/факт. Для пары возможны два слоя: прежнее постоянное знание и временное текущее. ID — непустые, до 160 символов, без управляющих знаков; значения и причины — до 8192 символов. Ограничение размера файла может сработать раньше ограничений отдельных полей; прежний файл при отказе не заменяется.

Операции с изменяемой сессией принадлежат потоку её создания; только LoopWork.Dispose допускает рабочий поток. Отметка поколения защищает от запоздалой работы по ошибке, а не от произвольного кода самой игры.

MCP-интеграция использует API Unity Pipeline 0.8.0-exp.1. Для других версий Pipeline или при его отсутствии сборка адаптера исключается; ядро остаётся доступным. Команда подключения: unity mcp --project-path <полный-путь-проекта>. Четыре команды loopkit_* только читают; сервера в Player нет.

Компоненты инспектора и постоянная память

API Контракт
CapturePersistentMemory Только постоянные факты мира и постоянные исходные знания; без времени и состояния сцены.
RestorePersistentMemory Валидация и глубокая копия до изменения; отмена, ожидание, замена памяти, восстановление/проверка мира на нулевом времени.
LoopMemoryFile JSON до 4 МиБ, атомарная замена и прежний .bak (сам не загружается); совпадение схемы, ID описания и ID постоянных фактов. Изменения расписания память не ломают.
Revision / MemoryRevision Счётчики изменений для синхронизации и постоянного сохранения; чтение не вызывает обработчиков.
LoopClockBehaviour.RememberAcrossRuns Автозагрузка и сохранение одной галочкой; MemoryPath относительно persistentDataPath, если не абсолютный.
LoopClockBehaviour.RecoverMemoryFromCurrentSession() Явное восстановление после ошибки памяти и завершения Start. Копирует существующие основной файл и .bak в уникальные .recovery-<id>, затем записывает текущую постоянную память. Возвращает false во время загрузки/группы событий или при неисправной сессии. Файловая ошибка задаёт PersistenceError и оставляет автосохранение отключённым; успех включает его. Не загружает старые улики, не сбрасывает мир и не меняет состояние запуска.
LoopTimeSource По умолчанию GameTime; RealTime выбирается явно. Ожидание сброса в обоих случаях реальное.
LoopCueEvents.TryInvoke ID события и исходный LoopStamp; отклоняет старое поколение. Группа UnityEvent синхронна.
RestartLoop / LoadMemoryFromEvent Void-методы для UnityEvent; переход после завершения группы. Последний запрос перехода имеет приоритет. Внутри группы Restart() и LoadMemory() возвращают null: переход начнётся после неё.
LoopKnowledgeGate Условие наблюдатель/факт/значение, объекты и события; пересчёт после синхронизации/сброса/загрузки, включая неактивные цели.
LoopKnowledgeAction.Learn Знание, срок, источник и причина из инспектора; факты мира не меняются.
LoopFactAction.Apply Изменяет истину мира без обучения наблюдателей.
LoopTimedRoute Зафиксированные неподвижные мировые маркеры, возрастающее время, плавный/мгновенный переход; участник сброса, без обхода препятствий.
LoopClockComponent.BindClock Вызывается после назначения часов созданному компоненту. Смена/снятие привязки во время сброса любой из сессий или привязка к неисправной целевой сессии отклоняется до изменения старой привязки и возвращает поле clock. Повторите после завершения перехода/исправления. Awake часов записывает ошибку компонента в Console вместе с объектом и продолжает привязку остальных.
LoopNavMeshRoute Необязательная сборка Navigation 2.x; нужны NavMesh и агент. Ведёт агента на любой скорости часов; пауза часов останавливает движение; перемотка, загрузка и сброс переносят точно; проверка сброса допускает притяжение к NavMesh в пределах радиуса агента.
LoopClockBehaviour.RestartAndRun Void-действие UnityEvent: сброс, ожидание успешного восстановления/проверки и запуск. Новый сброс или загрузка отменяет прежний запрос продолжения.

Требуется Unity 6000.5.7f1. Рецепты инспектора, восстановление после ошибок файла и пример описаны в руководстве.
