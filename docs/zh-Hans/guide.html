LoopKit 使用指南

需要 Unity 6000.5.7f1。包中包含标准 Unity 组件、独立 C# 核心和两个可导入示例。不需要模型或在线服务。工具界面与文档提供英语、俄语、西班牙语和简体中文。

在 Inspector 中开始

  1. 通过 Package Manager → My Assets → Import 导入 Asset Store 包，或通过 Assets → Import Package → Custom Package 导入本地 .unitypackage。UPM 版本使用 Package Manager → Add package from disk（package.json）或 Add package from tarball（.tgz）。
  2. 在 Project 中创建 Strange Euphoria XR → LoopKit → Loop definition。指定稳定且唯一的 ID，添加世界事实和日程事件。
  3. 在场景对象上添加 LoopClockBehaviour，指定定义，设置起始时分、速度及游戏时间，勾选启动时运行。
  4. 打开 Tools → Strange Euphoria XR → LoopKit → Workbench。语言选择器也会更新组件 Inspector。

Asset Store 版本位于 Assets/StrangeEuphoriaXR/LoopKit，已包含 Documentation 和 Samples。UPM 的指南位于 Documentation~，示例源文件位于 Samples~；使用前须通过 Package Manager → Samples 导入示例。每个项目只保留一份 LoopKit。需要标准 Unity Audio、IMGUI、JSON serialization、Physics 与 UIElements 模块；可选集成另行安装。

跨游戏启动保留线索

勾选时钟上的跨游戏启动保留记忆，即可自动保存和读取永久事实及观察者的持久知识。相对路径基于 Application.persistentDataPath，{definition} 替换为经过转义的定义 ID。不同游戏、存档槽和独立时钟应使用不同文件。

使用 LoopKnowledgeAction：指定时钟、观察者 player、事实 ID、来源和原因，选择跨循环，将 Learn 连接到按钮、触发器或日程事件。读取世界事实不会自动让任何角色学会它。

读取会开始新循环：取消旧操作，等待其真正结束，替换永久记忆，恢复所有注册的场景参与对象并验证世界。临时事实和认知被清除；临时矛盾不会破坏永久记忆基线。即使已注册 Reset Transform，也能读取。

永久数据变化及成功重置后自动保存；初始化成功后暂停应用或退出时也会保存。JSON 限制为 4 MiB，文件原子替换，上一份保留为 .bak 供手动恢复；LoopKit 不会自行读取 .bak。版本、定义 ID 以及永久事实 ID 集合必须一致。游戏更新中移动、添加或删除日程事件不会使已保存的记忆失效；添加、删除或重命名永久事实需要新的记忆路径或自行迁移。启用自动记忆后，无效的启动文件，或已进入重置但等待/验证失败的读取，会使自动保存保持禁用，启动时运行也不会启动时钟：由游戏决定向玩家提供什么。若手动读取在转换前被拒绝，例如 JSON 无效或指纹不匹配，现有会话仍然有效：自动保存继续使用选定路径，并可能在永久数据变化后替换该文件。时钟 Inspector 显示技术详情。继续前请保留原文件，并选择正确的路径/定义或明确迁移后的新存档槽。文件存储在 Windows 上验证；它不是云同步，也不是任意场景序列化。

若要继续使用当前游戏中已经获得的线索，请在持久化出错后显式调用 LoopClockBehaviour.RecoverMemoryFromCurrentSession()。它先将现有主文件和 .bak 分别复制到存档旁以 .recovery-<unique-id> 结尾的文件。两份复制均成功后，才原子写入当前永久事实和持久线索；不会导入旧线索。已有恢复备份不会被覆盖，重试时也一样。复制或写入失败会返回 false、设置 PersistenceError 并保持自动保存禁用；当前线索仍保留在内存中。恢复要求 Start 已完成、会话有效，且不处于读取过程或 Inspector 事件组内。此操作不会重置、推进或启动循环。如果会话发生故障，请先修复原因并成功重置。The Last Bell 在开始和暂停菜单中显示错误及恢复按钮。仅在希望将当前线索作为新存档时选择该操作；原文件仍保留在单独的恢复备份中。

在 21:30 打开门

在定义中添加事件 open_door，勾选使用一天中的时间并设置 21:30。给激活的场景对象添加 LoopCueEvents，选择时钟和相同 ID，将 Actions 的 UnityEvent 连接到门的 GameObject.SetActive(false)。给门添加 LoopResetTransform，指定相同时钟与唯一参与对象 ID。

事件每个循环仅执行一次，顺序稳定。秒数默认相对循环起点，早于起始时刻表示次日。ID 和作者输入的数据不翻译。延迟调用必须保留原始代次标记。每组 UnityEvent 同步执行；时钟的 RestartLoop, RestartAndRun 与 LoadMemoryFromEvent 在该组返回后才切换循环。同一组最后提出的切换请求生效。直接调用底层会话切换的代码，需要自行协调回调边界。

玩家知道密码时显示按钮

添加 LoopKnowledgeGate，指定观察者 player 与密码事实 ID。把按钮放入已知时启用的对象；也可要求特定值，添加未知状态的对象或事件。在学习、读取、重置后的时钟同步或帧末重新判断。时钟甚至能重新启用此组件所在的未激活对象。请将时钟放在受控对象之外。禁用组件本身会停止判断。在时钟之后加载的场景中，对象在加载时必须处于激活状态，否则请自行调用 BindClock()（Reset Transform 调用 RegisterInitialState()）。

艾玛在 22:00 到达厨房

添加 LoopTimedRoute，指定唯一 ID 和角色 Transform。在角色层级之外创建固定目标标记，按严格递增的秒数或 HH:MM 添加路线点。可选择插值或到时切换。绑定时捕获标记的世界姿态。时钟的 Advance/AdvanceTo 会立即设置精确的计划姿态，短时间跳转也一样。

路线负责恢复并验证角色。不要在同一角色上添加 Reset Transform，系统会报告所有权冲突。Transform 路线不包含避墙。运行时生成对象需先配置字段并调用 BindClock()，然后再修改角色。物品栏、动画、父对象/缩放变化及重建已销毁对象需要自定义参与对象。

LoopNavMeshRoute 是独立可选程序集，仅在存在 com.unity.ai.navigation 2.x 时启用。指定 NavMeshAgent 并烘焙合适的 NavMesh。正常时间推进时（任何速度）由代理寻路，时钟暂停时停止代理；跳转、读取或重置时 Warp 到计划姿态。重置验证接受代理在 NavMesh 上吸附后的起点，误差在其半径以内。位于 NavMesh 之外的姿态会使重置失败，并在 Console 中报告。标记必须位于烘焙表面上。基础包不会安装 Navigation。

暂停与解释

游戏时间使用 Time.deltaTime，因此 Time.timeScale = 0 会停止时钟。真实时间明确忽略 timeScale。速度表示每个时间源秒对应的循环秒数。重置等待始终使用真实时间。手动跳转可以推进暂停的时钟。代码也可使用独立的 Pause(owner)/Resume(owner) 暂停所有者。

Workbench 将按观察者筛选的知识与原因日志并排显示。选择一行即可查看完整来源、原因、范围和时间。日程区分已执行与待执行事件；世界事实显示实际值。角色可能相信错误或过时的信息，知识不等于事实。重置验证显示具体参与对象的问题。日志仅保留最近 512 条，不是无限持久审计记录。若某个组件在绑定或刷新时抛出异常，LoopKit 会在 Console 中连同对象记录该异常，并继续更新其余组件；刷新错误每个循环只报告一次。

示例

UPM 版本需在 Package Manager → Samples 导入 The Last Bell；Asset Store 版本已包含示例。在 Unity 6000.5.7f1 的 URP 17.5 项目中，打开示例文件夹内的 Prepared/TheLastBell.unity，然后进入 Play mode。Asset Store 版本的路径为 Assets/StrangeEuphoriaXR/LoopKit/Samples/LastBell/Prepared/TheLastBell.unity；从 UPM 导入后，场景位于 Assets/Samples/LoopKit/1.0.0/The Last Bell/Prepared。Prepared/Prefabs 包含 12 个可复用的模型预制件。准备好的场景和材质需要 URP；LoopKit 核心不依赖 URP。使用 Built-in Render Pipeline 时，选择 Tools → Strange Euphoria XR → LoopKit → Create last bell scene，生成使用 Standard 材质的场景。URP 项目也可继续使用此生成器。

WASD/方向键行走，E 互动，Tab 查看线索，Esc 暂停。完整谜题需要三个循环：了解柜子密码；取保险丝并阅读手册；提前应用记住的信号顺序并通知信使。菜单、线索和结局支持四种语言。重启 Player 后线索仍在，但实物不会跨循环保留。场景包含原创 Blender 模型：车站、列车、庭院、角色及谜题物品。无需其他插件或 AI 模型。

A second chance 是更小的英语示例：六秒后读取 2417，重置后在信使五秒离开前打开门。

核心、自定义系统与 MCP

CaptureCoreState/RestoreCoreState 保存时钟、已执行事件前缀、事实和知识。仅核心读取会拒绝已注册的世界参与对象。需要永久知识和重置世界时，使用 CapturePersistentMemory/RestorePersistentMemory。两者都在修改前验证，并使旧操作失效。底层操作真正结束前不得释放 LoopWork。恢复失败会保持停止；修复原因后重试。会话仅由创建线程修改，只有 LoopWork.Dispose 可以从工作线程调用。

LoopRehearsal.Run 检查逻辑分支，不模拟物理、画面或寻路。只读 MCP 适配器精确支持 Unity Pipeline 0.8.0-exp.1。通过 unity mcp --project-path <项目绝对路径> 连接；loopkit_status、loopkit_schedule、loopkit_knowledge、loopkit_reset_report 仅读取明确选定的时钟与观察者。其他版本排除适配器。Player 内不包含控制服务器。

自动重复循环

要自动重复循环，将最后一个日程事件连接到 LoopClockBehaviour → RestartAndRun。时钟在取消旧工作、等待结束并成功验证重置后继续运行。RestartLoop 仅重置并停止。失败或被新请求替代的重置不会启动时钟。Workbench 与运行中时钟的 Inspector 提供相同的 重置并运行 操作。事件会看到其精确时间边界上的 Transform 路线姿态，包括时间跳转。NavMesh 路线在正常 tick 中使用代理移动，在显式跳转/重置时 Warp；正常寻路不保证在事件时刻到达目标姿态。销毁活动时钟时，如果会话已就绪且有效，也会保存更改后的永久记忆。

1.0.0 版本

包含 Inspector 操作和知识条件、永久记忆、定时路线、重置验证以及 Editor 中的只读 MCP 诊断。The Last Bell 是一个需要三个循环完成的谜题，包含 12 个原创 FBX 模型；A second chance 是较小的示例。编辑器工具、指南、API 参考与 The Last Bell 支持英语、俄语、西班牙语和简体中文。
