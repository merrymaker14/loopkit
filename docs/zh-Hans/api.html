LoopKit — API 参考

命名空间：StrangeEuphoriaXR.LoopKit 是独立 C# 核心；.Unity 提供 Unity 组件和文件；.Editor 提供诊断和编辑；

using StrangeEuphoriaXR.LoopKit;

var loop = new LoopSession("courtyard-v1",
    new[] { new LoopCue("courier_leaves", 5, "courier", "leave", "gate") },
    new[] { new LoopFact("gate", "closed"), new LoopFact("code", "2417") });
loop.TryLearn(loop.Stamp, "player", "code", "2417",
    LoopLifetime.Persistent, "note", "Read the keeper's note.");
loop.AdvanceTo(6);
var reset = loop.BeginReset();
if (reset.Done && reset.Report.Succeeded) loop.Running = true;

如果重置未立即完成，在游戏更新中调用 reset.Tick(unscaledRealSeconds) 直到 Done。LoopClockBehaviour 已自动处理。

API 契约
LoopSession.SetSchedule 时钟停止、时间为零且无待完成工作时替换完整日程；修改前验证；同时间保持原顺序；最多 10000 个事件
ConfigureFacts 首次运行、写入、重置及创建工作之前；最多 10000 个定义
Advance / AdvanceTo 有限非负时间，上限 315360000 秒；回调看到准确事件边界
Pause / Resume 按对象身份区分；每个暂停方释放自己的暂停，重置会清除所有暂停方
Stamp / IsCurrent 会话身份和递增代次；重置、故障或 Dispose 后无效
BeginWork 底层任务或原生工作真正结束前保留句柄，仅确认取消不够
TrySetFact 显式世界状态，不会自动授予知识
TryLearn 观察者、观察值、范围、来源和原因，与世界真相独立
Knowledge.TryExplain 当前证据及来源、原因、获知时间和代次
TryRecordDecision 接受或拒绝及原因，不执行游戏操作
Knowledge.Journal 最近 512 条诊断记录，不是无限持久日志
Register(ILoopParticipant) 唯一 ID、取消、恢复、验证；重置前注册
Unregister(ILoopParticipant) 重置外立即移除。重置期间保留当前快照，在完成时、ResetFinished 之前移除，失败时也如此。当前回调/等待仍可能执行，已销毁的参与对象须能安全处理这些调用。移除不会结束工作 lease。
BeginReset 停止、失效旧标记、取消、等待、恢复并验证；默认超时为 10 真实秒；不自动继续运行
CaptureCoreState 只含时钟、事实、知识；事件分发和过渡期间禁止保存
RestoreCoreState 要求匹配版本、定义和指纹及合法事件前缀；已注册世界参与对象时拒绝加载
LoopCheckpointFile JSON 上限 4 MiB，同目录原子替换，前一版本保留为 .bak
LoopRehearsal.Run 新逻辑会话工厂、显式操作和断言，不模拟场景系统；值为空的 ExpectKnowledge 步骤接受任意已知值

最多 10000 个观察者/事实组合；每组可同时保存原有永久记忆和当前临时认知。ID 不可为空，最多 160 字符，禁止控制字符；值和原因最多 8192 字符。文件大小限制可能先触发，过大的存档不会替换原文件。

会话操作属于创建线程，只有 LoopWork.Dispose 可从工作线程调用。代次标记用于拒绝意外迟到的工作，不是阻止游戏任意代码的安全边界。

MCP 集成使用 Unity Pipeline 0.8.0-exp.1 的 API。缺少 Pipeline 或使用其他版本时排除适配程序集，核心功能仍然可用。通过 unity mcp --project-path <项目绝对路径> 连接。四个 loopkit_* 工具只读，Player 中没有服务器。

Inspector 组件与永久记忆

API 约定
CapturePersistentMemory 仅永久世界事实与持久证据基线，不含时钟或场景状态。
RestorePersistentMemory 修改前验证并深拷贝；取消、等待、替换记忆，在时间零恢复并验证参与对象。
LoopMemoryFile JSON 最大 4 MiB；原子替换并保留 .bak（不会自动读取）；版本、定义 ID 和永久事实 ID 必须匹配。日程变化不影响记忆有效性。
Revision / MemoryRevision 用于同步与永久保存的变化计数器；读取不调用回调。
LoopClockBehaviour.RememberAcrossRuns 一个复选框启用自动读写；MemoryPath 默认为相对 persistentDataPath，也可为绝对路径。
LoopClockBehaviour.RecoverMemoryFromCurrentSession() 在持久化出错且 Start 完成后显式恢复。将现有主文件和 .bak 复制到唯一的 .recovery-<id> 文件，再保存当前永久记忆。读取期间、Inspector 事件组中或会话无效时返回 false。文件操作失败会设置 PersistenceError 并保持自动保存禁用；成功后重新启用。不会读取旧线索、重置世界或改变运行状态。
LoopTimeSource 默认 GameTime；明确选择 RealTime。两者的重置等待均使用真实时间。
LoopCueEvents.TryInvoke 事件 ID 与原始 LoopStamp；拒绝旧代次。UnityEvent 组同步执行。
RestartLoop / LoadMemoryFromEvent UnityEvent 使用的 void 方法；该组结束后切换；最后提出的切换请求生效。在组内调用时 Restart() 与 LoadMemory() 返回 null，因为切换在组结束后才开始。
LoopKnowledgeGate 观察者/事实/值条件，对象激活和事件；同步、读取、重置后更新，也支持未激活对象。
LoopKnowledgeAction.Learn Inspector 配置知识、范围、来源和原因；不改变世界事实。
LoopFactAction.Apply 修改世界事实，不让观察者自动学会。
LoopTimedRoute 捕获固定世界标记，严格递增时间，插值或切换；负责重置，不包含避障。
LoopClockComponent.BindClock 为生成的组件指定时钟后调用。任一会话正在重置时更改/解除绑定，或绑定到故障目标会话，会在改变旧绑定前抛出异常并恢复 clock 字段。转换完成或故障恢复后重试。时钟的 Awake 会在 Console 中连同对象记录出错的组件，并继续绑定其余组件。
LoopNavMeshRoute 可选 Navigation 2.x 程序集，需要 NavMesh 和代理；任何时钟速度下都由代理寻路；随时钟暂停；跳转、读取和重置时 Warp；重置验证允许在代理半径内吸附到 NavMesh。
LoopClockBehaviour.RestartAndRun UnityEvent 的 void 操作：重置、等待成功恢复与验证，然后运行。新的重置或读取会取消旧的继续运行请求。

需要 Unity 6000.5.7f1。Inspector 配置、文件错误恢复和完整示例见指南。
