LoopKit overview

LoopKit guide

Requires Unity 6000.5.7f1. The package contains standard Unity components, an engine-independent C# core and two importable samples. No AI model or online service is needed. Tool UI and this documentation support English, Russian, Spanish and Simplified Chinese.

Start with the Inspector

  1. Import the Asset Store package through Package Manager → My Assets → Import, or open a local .unitypackage with Assets → Import Package → Custom Package. For a UPM distribution, use Package Manager → Add package from disk (package.json) or Add package from tarball (.tgz).
  2. Create Strange Euphoria XR → LoopKit → Loop definition in the Project window. Give it a stable, unique definition ID. Add world facts and schedule cues.
  3. Add LoopClockBehaviour to a scene object and assign the definition. Set starting hour/minute, speed and Game time. Check Run on start.
  4. Open Tools → Strange Euphoria XR → LoopKit → Workbench. Its language selector also updates component inspectors.

The Asset Store layout is Assets/StrangeEuphoriaXR/LoopKit, with Documentation and Samples already included. UPM keeps guides in Documentation~ and sample sources in Samples~; import a sample through Package Manager → Samples before using it. Keep one LoopKit installation per project. Standard Unity Audio, IMGUI, JSON serialization, Physics and UIElements modules are required; optional integrations are installed separately.

Remember clues between game launches

Check Remember across game launches on the clock. That is enough to enable automatic load/save of permanent facts and persistent observer evidence. Relative paths are under Application.persistentDataPath; {definition} in the file path becomes the escaped definition ID. Give different games, save slots or independent clocks different paths.

Knowledge comes from LoopKnowledgeAction: assign clock, observer player, fact ID, source and reason; keep Across loops and connect its Learn method to a button, trigger or schedule action. Reading a world fact does not teach it to anyone automatically.

Loading starts at the beginning of a new loop. It cancels old work, waits for actual settlement, replaces permanent memory, restores all registered scene participants, then verifies the world. Temporary facts and beliefs are cleared. A temporary contradiction never destroys the persistent baseline. This works when Reset Transform components are present.

Automatic saves follow persistent changes and successful resets; shutdown/pause also saves when initialized. Files are limited to 4 MiB and replaced atomically, keeping the previous file as .bak for manual recovery; LoopKit never loads .bak by itself. Schema, definition ID and the set of persistent fact IDs must match. Moving, adding or removing schedule cues in a game update keeps saved memory valid; adding, removing or renaming a persistent fact needs a new memory path or your own migration. With automatic memory enabled, an invalid startup file or a load that enters reset but fails verification/settlement keeps automatic saving disabled, and Run on start does not start the clock: the game decides what to offer the player. A manual load rejected before a transition (for example, invalid JSON or a different fingerprint) leaves the existing session active: its automatic saves continue at the selected path and may replace that file after a persistent change. Technical details appear in the clock inspector. Preserve the file and select the correct path/definition or an explicitly migrated/new slot before continuing. File storage has been checked on Windows; it is not cloud synchronization or arbitrary scene serialization.

To continue with the clues already in the current session, explicitly call LoopClockBehaviour.RecoverMemoryFromCurrentSession() after a persistence error. It first copies any existing primary file and .bak into separate files ending in .recovery-<unique-id>, next to the save. Only after both copies succeed does it atomically write the current permanent facts and persistent evidence; older clues are not imported. Existing recovery copies are never replaced, including on a retry. An archive/write error returns false, sets PersistenceError and leaves automatic saving disabled; the current clues remain in memory. Recovery requires Start to have completed and a valid session outside a load or designer-event group. It does not reset, advance or start the loop. For a faulted session, correct the cause and complete a successful reset first. The Last Bell shows this error and the recovery action in its start/pause menu. Choose the action only when you want the current clues to become the new save; the original files remain in their recovery copies.

Schedule an action at 21:30

Add a cue to the definition, set its ID (for example open_door), enable Use time of day and enter 21:30. Add LoopCueEvents to an active scene object, select the same clock, add a binding with that ID and connect its Actions UnityEvent to the door's GameObject.SetActive(false). Add LoopResetTransform to the door and give it the same clock and a unique participant ID.

Cues fire once per loop in stable time order. Seconds are relative to loop start unless time of day is selected; an earlier time of day means the next day. Cue ID and actor/action/target IDs are user data and are not translated. A delayed caller must retain the original generation stamp. Each UnityEvent action group is synchronous; clock RestartLoop, RestartAndRun and LoadMemoryFromEvent defer transitions until that group returns. The last transition requested in one group wins. Code that calls the lower-level session transition directly must coordinate its own callback boundary.

Show a button when the player knows the code

Add LoopKnowledgeGate, observer player, and the code fact ID. Assign the button to Objects enabled when known; optionally require an exact value and add unknown objects or UnityEvents. It re-evaluates at clock synchronization/end of frame after learning, loading and resets. Its clock can reactivate even this gate's own inactive object. Keep the clock outside controlled objects. Disabling the component itself disables evaluation. Objects in a scene loaded after the clock must be active when that scene loads; otherwise call BindClock() (and RegisterInitialState() for Reset Transform) yourself.

Send Emma to the kitchen at 22:00

Add LoopTimedRoute with unique participant ID and actor Transform. Create stationary destination markers outside the actor hierarchy. Add strictly increasing points, using seconds or HH:MM. Choose interpolation or a step at the specified time. Marker world poses are captured on binding. Clock Advance/AdvanceTo evaluates the exact authored pose immediately, including short skips.

The route restores its actor to its initial route pose and verifies it on reset. Do not put Reset Transform on the same actor: conflicting ownership is diagnosed. The Transform route does not avoid walls. For a spawned route, assign fields and call BindClock() before changing the actor. Arbitrary inventory, animation, parent/scale changes or destroyed-object reconstruction need your own participant.

LoopNavMeshRoute is an optional assembly enabled only with com.unity.ai.navigation 2.x. Assign a NavMeshAgent and bake a suitable NavMesh in your project. It steers the agent during normal clock movement at any speed, stops with the clock, and warps to the authored pose for skips, loads and resets. Reset verification accepts the start position the agent snapped to on the NavMesh, within its radius. A pose outside the NavMesh fails the reset and is reported in the Console. Keep markers on the baked surface. The base package does not install Navigation.

Pause, inspect and understand

Game time uses Time.deltaTime: Time.timeScale = 0 stops the clock. Real time deliberately uses unscaled time. Speed means loop seconds per second of the selected source. Reset settlement always uses unscaled real time. Manual time skips are explicit and can advance a paused clock. Code may also use independent Pause(owner)/Resume(owner) owners.

Workbench shows observer-filtered evidence next to the reasons journal. Select a row for the complete source, reason, scope and time. Expand Schedule for executed/upcoming cues and World facts for actual values. Facts are not the same as evidence: a character may hold a false or outdated belief. Reset verification shows concrete participant failures. The journal keeps the last 512 entries, not an unlimited saved audit log. If one component throws while binding or refreshing, LoopKit logs the exception with that object and keeps updating the others; a refresh error is reported once per loop.

Samples

For UPM, import The Last Bell in Package Manager → Samples. In an Asset Store installation the sample is already included. In a URP 17.5 project on Unity 6000.5.7f1, open Prepared/TheLastBell.unity inside the sample folder and enter Play mode. In the Asset Store layout its path is Assets/StrangeEuphoriaXR/LoopKit/Samples/LastBell/Prepared/TheLastBell.unity; after UPM import it is under Assets/Samples/LoopKit/1.0.0/The Last Bell/Prepared. Prepared/Prefabs contains 12 reusable model prefabs. The prepared scene and materials require URP; the LoopKit core does not. For the Built-in Render Pipeline, choose Tools → Strange Euphoria XR → LoopKit → Create last bell scene to generate a scene with Standard materials. The same generator remains available in URP.

Walk with WASD/arrows, interact with E, open evidence with Tab and pause with Esc. The complete authored mystery needs three loops: learn the locker code, obtain a fuse and read the handbook, then use the remembered sequence early and warn the courier. Its menu, clues and ending support all four languages. Clues survive a Player restart; physical items do not. The scene includes original Blender models of the station, train, courtyard, characters and puzzle items. No other plugin or AI model is required.

A second chance remains a smaller English gameplay example: read 2417 after six seconds, reset, and open the gate before the courier leaves at five seconds.

Core saves, custom systems and MCP

CaptureCoreState/RestoreCoreState save clock, executed cue prefix, facts and evidence. Core-only loading intentionally refuses registered world participants. Use CapturePersistentMemory/RestorePersistentMemory for durable knowledge with a reset world. Both validate before mutation and invalidate stale work. Keep LoopWork leases until the underlying work really settles. Failed restoration remains stopped/faulted; retry after fixing its cause. All session mutations use the creating thread; only LoopWork.Dispose is worker-safe.

LoopRehearsal.Run checks logical story branches, not physics, rendering or navigation. The read-only MCP adapter targets exactly Unity Pipeline 0.8.0-exp.1. Connect with unity mcp --project-path <absolute-project-path>; loopkit_status, loopkit_schedule, loopkit_knowledge, loopkit_reset_report inspect the explicitly selected clock/observer. Other versions omit the adapter. No controlling server is included in Player.

Repeat the loop automatically

For an automatic loop, connect a final schedule cue to LoopClockBehaviour → RestartAndRun. It waits for cancellation, settlement and successful reset verification before running again. RestartLoop resets and stops. An unsuccessful or superseded reset never starts the clock. Workbench and the live clock Inspector expose the same Reset and run action. Events observe Transform routes at their exact cue boundary, including time skips. NavMesh routes steer during normal ticks and warp during explicit skips/resets; normal navigation does not guarantee arrival at a cue boundary. Dirty permanent memory is also saved when an active clock is destroyed, provided the session is ready and valid.
